# 公开数据负载

准备方式见根目录 [README](../README.md#数据准备)。大文件和本地快照不进入版本库。

每套准备结果为 `prepared/<dataset>.sqlite3` 和 `.meta.json`，兼容旧版 JSONL 池。

完整原始文件和校验清单保存在 `raw/`。SQLite 保存压缩后的回放字段、参考答案与逐轮长度索引；Parquet 中不参与回放的字段仍完整保留于源文件，通过 `_cloudbench_source` 的文件名、行号和字段名定位。运行时只读取选中的会话，逐轮构造前缀，不把整套数据或重复历史放进内存。参考答案不会发给模型。

旧版 JSONL 一行表示一个 RAG 请求或一个 Agent 会话：

```json
{"id":"source-id","turns":[{"messages":[{"role":"user","content":"问题与材料"}],"input_tokens":120}],"reference_answer":"仅供后续评分，不发给模型"}
```

Agent会话的每个turn保存该轮完整原始前缀与可选tools；回放严格按turn顺序，后续不使用当前生成结果。元数据记录实际抽取样本数、逐轮请求数、长度分布、来源、抽样区段、tokenizer与数据哈希。长度分布按请求计，样本数按会话计，两者不同。

默认导入所选来源分区的全部记录、全部会话轮次。`raw_count` 是原始记录数，`item_count` 是可回放数，`skipped_count` 记录无法适配的数量；所有来源记录和对应错误均可定位。元数据的 `scope` 明确版本和分区，`complete` 区分完整导入与主动抽样。

测试数量由创建测试时填写，超出可用量会报错，不重复补齐。长度筛选仅影响本次回放，不删除源数据。完整公开数据也不等于生产流量分布，业务占比需在测试配置中确定。
